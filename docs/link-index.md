# リンクサジェスト索引（他アプリ共有用）

couchNotes は、`[[...]]` リンク入力時のサジェスト候補（既存ノート名＋どこかで言及済みの
未作成ページ名）を、**CouchDB 上のドキュメント**として書き出す。同じ CouchDB を読み書きする
他アプリは、これを取得するだけで同じサジェストを再現できる。

書き出しは couchNotes 側の `LinkIndexPublisher`（`couchNotes/LinkIndexPublisher.swift`）が担う。
他アプリ側は「読むだけ」でよい。

## なぜ「フォルダ別」の複数文書なのか

端末ごとに同期するフォルダ（トップレベル）が異なる（**部分同期**）。各端末はローカルに
自分の同期フォルダ分のノートしか持たないため、全体を1文書に書くと端末どうしで上書き合戦になる。
そこで **トップレベルフォルダ単位で1文書ずつ**書き出す:

- 端末が違えば書くフォルダの文書が違う → 上書きしない。
- 同じフォルダを同期する端末どうしは内容が一致する → 競合しない。
- 全文書の**和集合が実質「全ノート」**になる（各フォルダをどれかの端末が同期している限り）。
- ルート直下のノートは全端末が同期するので、専用の「ルート文書」に入る。

## ドキュメント ID と発見方法

すべて次の接頭辞で始まる:

```
couchnotes_linkindex_
```

- ルート: `couchnotes_linkindex_root`
- 各フォルダ: `couchnotes_linkindex_<16桁hex>`（フォルダ名を小文字化した SHA256 の先頭16桁。
  URL エンコード不要にするため。ID を自前で組み立てる必要はなく、下記の列挙で見つける）

**読み手は ID を組み立てず、接頭辞で列挙する**のが確実:

```
GET {baseURL}/{db}/_all_docs?include_docs=true
      &startkey="couchnotes_linkindex_"
      &endkey="couchnotes_linkindex_￰"
```
（`startkey`/`endkey` は JSON 文字列。URL エンコード例:
`startkey=%22couchnotes_linkindex_%22&endkey=%22couchnotes_linkindex_%EF%BF%B0%22`）

各行の `doc` が下記スキーマの索引文書。旧・単一文書 `couchnotes_linkindex`（末尾 `_` なし）は
この範囲に**入らない**ので拾われない（移行後は couchNotes が削除する）。

## スキーマ（1フォルダ＝1文書）

```json
{
  "_id": "couchnotes_linkindex_root",
  "_rev": "3-...",
  "type": "couchnotes-linkindex",
  "version": 2,
  "folder": "Work",
  "generatedAt": "2026-07-28T12:34:56Z",
  "links": [
    { "key": "ページ名",  "title": "ページ名",  "path": "work/ページ名.md", "exists": true },
    { "key": "mynewpage", "title": "MyNewPage", "exists": false }
  ]
}
```

| フィールド | 意味 |
|---|---|
| `folder` | この文書が表すトップレベルフォルダ名（大小保持）。**ルート文書では省略（=なし）**。 |
| `links[].key` | 照合用の正規化キー（**常に小文字**。エイリアス`|`・見出し`#`・`.md` は除去済み）。照合は大小区別なし。 |
| `links[].title` | 挿入・表示用の名前。**大文字小文字は書かれたまま**（実在ノートはノート名、未作成は `[[...]]` に書かれた表記）。リンクは `[[title]]` の形で挿入する想定。 |
| `links[].path` | 実在ノートの LiveSync `_id`（＝小文字パス）。`exists=true` のみ。ノート本体を開く／`_id` 照合に使える。`exists=false` には無い。 |
| `links[].exists` | `true`=実在ノート、`false`=言及のみの未作成ページ。 |
| `type` | 固定値 `"couchnotes-linkindex"`。 |
| `version` | スキーマ版（現在 2）。 |
| `generatedAt` | 生成時刻（ISO8601）。 |

`_id`/`_rev` は CouchDB のメタ。候補生成には各文書の `links` を使う。

## 読み手アプリでの使い方

### A. 全フォルダを使う（全ノートをサジェスト）

1. 上記の `_all_docs` 範囲取得で索引文書を**全部**取得。まだ1件も無ければ候補なし（エラーにしない）。
2. すべての `links` を**マージ**する。**同じ `key` は集約し、`exists=true` を優先**して1件に
   まとめる（`exists=true` のエントリは `title`/`path` を持つ）。
   - これが重要: あるフォルダで未作成（`exists=false`）に見えるキーが、別フォルダには実在
     ノートとして存在することがある。マージで `exists=true` を優先すると正しく解決される。
3. ユーザーが `[[query` と打ったら、`query` を **小文字化**（保険で **NFC 正規化**も）して、
   各エントリの `key` に **前方一致 →（無ければ）部分一致** でフィルタ。
4. 候補は `title` を表示。`exists=false` は「未作成」として淡色などで区別してよい（任意）。
5. 選択で本文に `[[title]]` を挿入。必要なら `path` でノート本体を開く／`_id` 照合に使う。

### B. 特定フォルダだけ使う（フォルダ指定）

- 列挙した文書のうち、`folder` フィールド（ルートは無し）で**使いたいフォルダの文書だけ**選び、
  その `links` を使う（A のマージを対象文書だけで行う）。
- あるいは A で全マージした後、`path` の接頭辞（例 `work/`）で候補を絞ってもよい
  （`exists=false` は `path` が無いので、その扱いは用途に応じて決める）。

### 更新・キャッシュ

- 起動時＋数分キャッシュで十分。効率化するなら、各文書の `_rev` 変化、または `_changes` フィードで
  `couchnotes_linkindex_` 接頭辞の文書の更新を検知して、変わった文書だけ取り直す。
- DB 全体をローカル複製している実装なら、これらの文書もローカルに来る。読み手側で
  「`.md` で終わらない ID はノートとして扱わない」を守れば、ローカルから直接読める。

## 更新タイミングと一貫性（書き出し側の挙動）

- `.noteStoreDidChange`（ノート push・`_changes` 取り込み・reconcile）を単一フックにデバウンス更新。
- **フォルダごと**に索引集合のフィンガープリント（SHA256）を前回と比較し、**変化したフォルダの
  文書だけ** PUT する。通常のタイピングでは集合が変わらず、ネットワーク書き込みは発生しない。
- 複数端末が同じフォルダ文書を書いても内容は一致するため競合しない。稀な 409 は `_rev` を
  取り直して1回再試行（派生データなので最終書き込み優先）。
- 索引文書の ID は `.md` で終わらないので、couchNotes 自身の longpoll を再発火させない
  （フィードバックループにならない）。
- 実在判定（`exists`）は各端末のローカル全体で行うため、単一フォルダ文書だけを見ると別フォルダの
  実在ノートを `exists=false` と表すことがある。**読み手は全文書マージ時に `exists=true` を優先**して解決する。
